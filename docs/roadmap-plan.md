# Roadmap plan: the issue backlog, and small release packages

**Дата:** 2026-10-28. **Статус:** план согласован с владельцем форка; каждый пункт внедряется отдельным релизом,
решения уточняются реальными измерениями до внедрения (никаких предположений).

Контекст: три issue апстрима разобраны (https://github.com/ARahim3/DigUp/issues/151, 153, 162); проверено, что
никто из ~30 форков их не решал (все — ванильные клоны, единственный живой дериватив — Sebastianhayashi/Farshelf,
macOS-каталог на стадии дизайн-документов). Апстрим-мастер от 26.10: IME-фикс, сайт, правило скрытых папок — ни
одного из трёх пунктов там нет; find-similar обещан автором в v0.7.0 (беты уже идут).

## P0 — стамп протокола и «тонкие» релизы

**Зачем:** полный zip весит ~470 МБ, из которых ~99% — helper (CUDA-рантайм и DLL). Но shell и helper — версионная
пара: 0.1.4 менял обе стороны, и exe-only обновление той версии сломало бы пару. Стамп делает «не сломало»
машинным свойством, после чего релиз может выкладывать маленький `-shell-only.zip` (~3 МБ), когда helper не менялся.

**Решение:**
- `HelperProtocol.version = 1` (Swift, `Sources/digup/HelperProtocol.swift`) и `HELPER_PROTOCOL = 1` (Rust,
  `main.rs`) — парные константы; номер растёт при любом изменении формы протокола (поля, команды, семантика).
- Шелл передаёт `--protocol <n>` в **каждый** спавн helper'а (`Shell::launch` — точка всех запусков, плюс прямой
  `Command` в `index_opens` и `estimate`, плюс стартовый search-Launch). Helper стрипает аргумент до разбора и при
  несовпадении выходит с ошибкой «update the whole package, not just DigUpPlus.exe». Ручные CLI-запуски без флага
  работают как раньше.
- `scripts/package-portable.sh` печатает `HELPER SHA256` и по `SHELL_ONLY=1` дополнительно собирает
  `.build/DigUpPlus-<version>-shell-only.zip` (exe + portable.txt + notices).
- Шаблон нот релиза: при неизменном helper — первой строкой «⚠️ Updating an existing install? … shell-only.zip …
  replace DigUpPlus.exe beside helper\ … close DigUp Plus first»; при изменившемся — стандартная шапка без намёка.
- README → Install: абзац «Updating».

**Проверка:** mismatch-тест живьём (`--protocol 999` → ошибка с внятным текстом); пара с совпадающим номером
работает как раньше (индексация идёт); `cargo test`/`clippy`/`node --check` зелёные; `swift build` зелёный.

## P1 — #151: z-гейт прячет результаты на малых корпусах

**Суть (воспроизведено на нашем движке, 2026-10-28):** кандидат проходит гейт `z ≥ 2.0`; для population-std
z_max = √(n−1), значит на 1–4 векторах порог недостижим математически. Репродукция: 3 файла, релевантный документ
cosine 0.7257 / z 1.398 → дефолтный поиск `[]`, `--zgate 0` находит. Замеры на этом же корпусе: нерелевантные
запросы 0.51–0.55, смежные 0.61.

**Решение (внедрено 2026-10-28, правило выбрано измерениями):** sweep по корпусам N ∈ {3, 5, 8, 12, 16, 20} показал
зону сбоя ровно N ≤ 5 (z релевантных 1.39–1.96 при пороге 2.0; N = 8 проходит 3/3), и чистое разделение по cosine:
релевантные ≥ 0.72 в зоне сбоя, нерелевантные ≤ 0.55, смежные 0.59. Внедрено: при < 8 масштабирующих векторах
модальности (`Searcher.smallCorpusVectors`) z-гейт не применяется, кандидат проходит по абсолютному полу
`smallCorpusFloor = 0.600` — того же числа, что слабый слой Images. Acceptance выполнен: issue-корпус (3 файла)
находит релевантные дефолтным гейтом (0.726/0.723), нерелевантный запрос остаётся `[]`; sweep после фикса —
релевантные 3/3 на всех N, нерелевантные 0 утечек в зоне bypass, N ≥ 8 без изменений; юнит-тесты границы
(`aSmallCorpusAdmitsByCosineAndStillRejectsUnrelated`, `aGroupLargeEnoughKeepsTheZGate`); Swift 138 тестов (только
известный symlink-провал), cargo 58/58.

## P2 — #153: включаемое определение датасетов

**Суть:** папки, похожие на датасеты, молча пропускаются краулером; пользователю с многими фотоподпапками нужна
настройка. **Находка:** половина уже есть — CLI-флаг `--include-datasets` → `IndexOptions.includeDatasets`
(Crawler.swift:211), приложению не хватает только галочки и проброса аргумента.

**Решение:** галочка в Settings → Folders («Include folders that look like datasets», дефолт off = поведение
апстрима); шелл добавляет `--include-datasets` в launch-аргументы, когда включена.
**Проверка последствий:** Estimator обязан получить тот же флаг (иначе прогноз разойдётся с фактом); фикс-папка,
триггерящая детектор → индексируется при on / пропускается с репортом при off; evals без изменений на дефолте.

## P3 — одно-референсное «Find similar» (#162)

**Суть:** правый клик по результату → искать визуально похожее. Вектор картинки уже лежит в индексе — ре-эмбеддинг
не нужен; ранжирование по cosine для Images уже есть (`by_cosine` + слои).
**Решение (внедрено 2026-10-28):** протокол поиска получил `"like": "<path>"` — хелпер резолвит вектор строки из
памяти Searcher'а (`vector(forFile:)`, де-квантизация fp16), ранжирование — готовым by-cosine путём с
`excluding:` для исходной строки; шелл: пункт «Find similar» в контекстном меню media-результатов, поле показывает
`similar: <имя>`, любой ввод/смена фильтра возвращает обычный поиск. Юнит-тест: ранжирование по cosine, референс
исключён (`aLikeSearchRanksByCosineWithoutItsReference`).
**Проверка:** swift-набор зелёный; живую проверку меню — на сборке.
**Метки/коллекции референсов — осознанно ждём v0.7.0 апстрима** и портируем их дизайн (беты идут, фича обещана).

## Порядок и каденция
